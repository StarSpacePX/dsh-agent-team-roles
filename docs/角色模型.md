# 角色模型

## 角色是什么

给 dsh 的 agent team 每个成员定义一个**角色**，每个角色是一枚独立可选的 agent preset。

- **角色 = preset。** 插件启动时把每个角色通过公开服务 `ctx.agentPresets.register(definition)` 注册进
  dsh，于是角色出现在 preset 选择器里，可以像内置的 `standard` 一样被选中。
- **只引用，不新增。** 角色的能力行不会凭空创造：它们来自部署里真实的 `standard` preset 快照
  （`lib/template/standard.plugins.json`），角色只在其上做**开关**（外加 AGENTS.md 面板的三个发现键）。
- **不碰现有文件。** 插件只写自己的数据目录（一个角色一个目录：`<id>/role.json` + `<id>/AGENTS.md`），
  不改 dsh 包、不改 shipped presets、不改 `~/.dsh/settings.yaml`。
- **两个挂载点。** 页签栏的「角色」页负责配置角色，页签栏的「群聊」tab
  负责显示团队消息（见 [群聊页签](群聊页签.md)）。

「角色」页里的能力行表支持三件事，都是为了在几十行里不迷路：

- **过滤框**：按包名 / 行 id / 行名做子串过滤。
- **只看被角色改过的行**：勾上后只剩带角色覆盖的行（左下角竖线标记的那些）。
- **整类开关**：每个分类标题行（以及 MCP 标题行）有一个三态复选框——**它就是全开 / 全关**，
  半选表示「这一类只开了一部分」。只作用于当前可见的行。点下去**整类立刻一起变**（乐观更新），
  改动先记进队列，120ms 内的多次点击合并成**一条** `set-switches` 发出去（见下一条），最后用回包
  里带的 `/state` 收尾。已经处于目标状态的行会被跳过，不会产生多余覆盖。
- **一个动作一个入口**（用户 m09281 2.）：原来分组行右边还摆着「全开 / 全关」两个中文按钮，
  和那个复选框做的是同一件事，**已删除**；第三列（按钮位）跟着去掉，标题行只剩「标题 / 整类开关」。
- **不再整表变灰，而且批量走一个请求**（用户 m09281 3. + m09376「批量 action必须做」）：
  旧版「全开 / 全关」会拿全局锁，一点下去所有分组复选框、MCP 复选框、工具栏按钮全部变灰，约 2 秒
  （19 个工具行 = 19 次 `set-override`，宿主侧每次都 `sync()` 一遍）。现在目标状态立刻画出来，
  只有**被点的那个复选框**自己进入「进行中」（`group:<分类>` / `mcp:*`），而请求是**一次手势一条**：
  `commitSwitches` 把改动记进队列、`SWITCH_BURST_MS`（120ms）窗口结束时合并成一条 `set-switches`，
  宿主侧一次写盘、一次重建预设（`store.upsert` + `sync` 各一次）。
  这就是成熟栈的通用做法——**声明式一次提交**（JSON Merge Patch / Kubernetes strategic merge patch /
  各家 batch 端点：客户端发目标状态，服务端原子应用）+ **客户端 debounce/coalesce**（乐观 UI、失败回滚）。
  失败时乐观覆盖会被收回并重新 `GET /state`，面板回到文件里真正写着的状态。
  ⚠️ `set-switches` 是宿主侧新增的 action ⇒ **要重启 dsh**；只刷新页面的话客户端已经会发它，
  而老宿主侧会把它报成未知 action。
- **分类可折叠**：点分类标题（`▾ 工具（19）`）就收起/展开这一类。MCP 面板的标题同理。

**这一版没有逐行 config 编辑器**（用户 2026-09-27 拍板：「把配置/还原功能去掉，我只要开关就行」）。
行名上的 tooltip 仍会显示该行的 config，供好奇的读者查看；`set-override` 的 `config` 参数依然存在，
AGENTS.md 面板在用。想清掉某一行之前留下的覆盖，用角色级的「全部还原（保留名字与 AGENTS.md）」，
或者行表上那个「还原默认」（只清行覆盖与 MCP 勾选）。


## 新建角色：显式角色 ID（§5.56，用户 m20207）

一句原文：「既然成员名称必须是英文，那你再给一行设置 id 不就行了，以后杜绝这种乱七八糟的东西」。

角色 id 就是成员名加前缀（成员名 = id 去掉 `team-`），以前只能由名字自动 slug（`lib/roles.js:212-227`）：
ASCII 名转 slug，**纯中文名没有 ASCII，就用码点哈希兜底**（`hash = (hash*31 + 码点) >>> 0` → `r` + base36），
所以「探查员」建成 `team-rfozlm` —— 没人认得出来，也不是用户选的。现在「新建角色」那一行多了第二个输入框：

- **`roleIdFromInput(value, prefix)`**（`lib/client.js`）：只留 `a-z0-9-`（其余折成 `-`，再去首尾），
  空则返回 `''`；带不带 `team-` 前缀都认，返回的一定是完整 id。前缀取自 `/state.presetPrefix`（兜底 `'team-'`）。
- **留空 = 老行为**：不传 `id`，宿主仍按名字 slug（`lib/host/commands-role.js:32` 接受显式 `body.id`，
  所以「懒得想 id」那条老路还在）。
- **敲下去就回显**：`角色 ID：team-qa-1 · 成员名：qa-1（spawn_teammate 用这个名字）`；
  非法字符时按钮**禁用**并说明「角色 ID 只能用英文小写字母、数字和短横线（例如 devtest、qa-1）。」
- **测试**：`tests/plugin/ui-and-log.test.mjs` 的 `§5.56` 一条（11 条源码断言：helper、正则、placeholder、
  显式传 `id`、两条提示、禁用条件）。**全量 5 个测试文件 176 / 176 pass**。
- **真机验收（3080，刷新即生效）**：输入 `QA-1` → `team-qa-1 / qa-1`、按钮可用；输入 `测试` → 非法提示、按钮禁用；
  输入 `devtest` → `team-devtest / devtest`。**纯客户端改动，刷新页面即可，不用重启 dsh**。

## 改角色 ID：目录、role.json、preset 三样一起换（§5.57，用户 m20310）

一句原文：「你还得给我改id的地方啊，就放在名字下面一行」。

详情面板的「名字」下面多了「角色 ID（成员名）」这一行 —— 选中哪个角色就填哪个（框里只写去掉前缀的成员名，
敲的时候带不带 `team-` 都行，`roleIdFromInput` 会补全）。id 同时是**目录名**、`role.json` 里的字段、以及注册
出去的 **preset id**，所以保存时 `update-role` 收一个 `newId`，宿主侧用新增的 `store.rename(id, nextId)`
一次换三样：先把目录挪过去（`rename(roleDir(...))`，角色自己的 `AGENTS.md` 就在目录里，跟着走），
再 `normalizeRole` 校验新 id 并重写 `role.json`，最后更新内存列表；注册名由 `commit` 把旧 id 记进
`removed` 卸掉、`ensureRegistered` 挂上新 id（`lib\index.js` 的 `commit` 会注销所有不在 `wanted` 里的 preset）。

- **不动的**：覆盖行（`overrides`）按**行 id** 存，跟角色 id 无关；角色的 `AGENTS.md` 内容和
  `agentsMd.dshHome`（指向角色目录）跟着目录走。
- **界面提示三态**（框下面只留这三种，要当场看见）：非法 → 「角色 ID 只能用英文小写字母、数字和短横线（例如 devtest、qa-1）。」；
  被占用 → 「已经有角色在用这个 ID：team-xxx」；改过了 → 「保存后：角色 ID … · 成员名 …（spawn_teammate
  用这个名字；**已经建好的成员不会跟着改名**）」。非法或被占用时保存按钮禁用。
- **常态说明收进 ⓘ**（用户 m03983：「把成员名这行描述放旁边说明里面」）：没改、也没错的时候框下面**不再常驻**
  「成员名：…」那行，改挂在「角色 ID（成员名）」标题右边的说明点里（`info('roleMemberName', …)`，
  文案键 `roleMemberName` 在 `lib/notes.js` 的 `DEFAULT_NOTES`，与客户端兜底逐字一致 —— 由
  `tests/notes-drift.test.mjs` 钉住）。
- **为什么要提醒成员名不会跟着改**：成员名用过就不可删、不可改（`TEAM_MEMBER_NAME_TAKEN`，见内部变更史 §5.53），
  改名只影响**以后**新建的成员。
- **错误路径原地不动**：占名（`角色已存在：…`）、非法 id（`角色 id 必须是 [a-z0-9][a-z0-9-]*…`）、
  内置 preset 名（`角色 id 不能是内置 preset：standard`）、空（`角色 id 不能为空`）—— 都在 `store.rename`
  动手之前挡下，目录不会半途搬走。
- **测试**：`tests/plugin/role-admin.test.mjs`（宿主一条）与 `tests/plugin/ui-and-log.test.mjs`（客户端一条）的 §5.57 —— 宿主一条（改名后旧目录的 `role.json` 读不到；
  新角色的 `dir` / `roleFile` / `agentsMdFile` / `agentsMd.dshHome` 都对；手写的 `AGENTS.md` 跟着目录走；
  `overrides['tool-web']` 原样；`result.removed` 含旧 id 且 `registered` 已换名；新 id 能再 `update-role`；
  四条错误路径 + 失败后原地不动）、客户端一条（13 条源码断言）。**全量 5 个测试文件 178 / 178 pass**。
- **宿主侧改动 ⇒ 必须重启 dsh 才生效**（客户端侧刷新页面即可）。
- **真机验收（2026-09-30，重启后）**：用户在面板上把「探查员」的角色 ID 改成 `select`（成员名 `select`），
  「开发测试」仍是 `devtest`。重启后的 `GET /state`：`roles = [team-select=探查员, team-devtest=开发测试]`、
  `registry = team-devtest, team-select`、`loaded = true`、`error` 与 `registryError` 都空；
  盘上 `~\.dsh\agent-team-roles\` 只剩 `team-select\` 与 `team-devtest\`，两份 `role.json` 的 `id` 与目录名
  一致，每个目录仍是 2 个文件（`role.json` + `AGENTS.md`，后者跟着目录走）；成员名册也照新 id 报
  「探查员」→ `select`。**改名链路（面板那一行 → `update-role.newId` → `store.rename` → 重新注册）整条走通。**
