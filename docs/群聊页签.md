# 群聊页签

## 会话里的「群聊」tab

插件有**两个挂载点**：页签栏的「角色」页（配置，见 [角色模型](角色模型.md)），
以及会话页签栏里的「群聊」tab（`conversation.view` slot，显示）。群聊 tab 的内容是**团队成员之间的消息**——
这恰好是 dsh 自带「智能体团队」UI 刻意不做的那一块（内置面板只有 roster 与任务板，
其 README 原文：「**没有 mailbox timeline**」）。

数据不靠猜：team 事件（`team/member` / `team/task` / `team/message/queued` /
`team/message/delivered`）**本来就是 Lead 会话日志里的事件**。客户端用
`session.eventSource.getSnapshot()` 能拿到一段连续事件窗口（**有界的尾部**，见 §5.48），
宿主侧另有 `/team-log` 把那个会话的**整份**日志折成投影（§5.50），客户端两边合并着用——
所以这个 tab **不需要动上游**，也不需要别的存储。

渲染规则（`foldTeamEvents`，纯函数，有单测覆盖）：

- `team/member` / `team/task` 按 id 取**最后一条**——它们是整值快照，不是增量。
- `team/message/queued` 按 `message.id` 去重后，按日志顺序进列表。
- `team/message/delivered` 只带 `messageId`，用来给已入列的消息回填「已送达」。
- `status === 'deleted'` 的任务不显示。

表头分几段，**按需出现**：`成员 N` 与 `消息 M` 一直在（`M` 是**当前周期内显示的条数**，见下文的周期收窄），
`排队中 K` 只在 K > 0 时出现，`任务 T` 只在有任务时出现，历史还没载完时会再补一段 `（历史未载完）`
（宿主侧的投影答上来时改显示 `整份日志`，见 §5.50）。
每条消息显示发送者与 `→` 接收者，**两个名字都是同一种实底白字 chip、只差颜色**（§5.59：用户 m00378
「发送接收者不需要层级区分，只有颜色，我只需要保证这一行是显眼的」），后面跟时间戳与状态；
状态色**独立**：绿色的「已送达」、红色的「未送达」（页头统计的「排队中 K」仍是橙色）。
每条消息的**整圈边框**用**发送者**的颜色（用户 m00727 澄清：「我说的是消息边框同色，不是卡片都改颜色」——
只染边框，卡片底色与文字保持原样），且平时只到 **40% 淡色**，鼠标停在某一条上才转成实色（§5.61）。

页面上的另外几处（§5.60 的五条要求 + §5.61 的减框改版，见 `tests/plugin/ui.test.mjs`）：

- **时间戳固定淡紫** `#c4b5fd`，不再跟着状态变色；「已送达 / 未送达」保持自己的绿 / 红。
- **顶部成员名单**（`devtest · active` 那一排）用自己的角色色做背景 + 白字（形状复用名字 chip）。
- **分区标题**（「角色依赖图」「消息流」）统一主题紫 `#6B21A8`。
- **周期条**（原「@ 统计周期」）去掉 `@`，整行放大到 13px 并给一层浅底，与左侧标题对齐。

版式（§5.61：用户 m00844「块的线条框框太多了，看起来不精致」→「按你的来」）：

- **线只用于分隔性质不同的东西**：页头、两个分区标题、依赖图行都不再画线，分段改为留白。
- **间距只有三档**：8（组内）/ 12（块内）/ 20（块间）；圆角统一 8，胶囊除外。
- **页头改成 stat 块**：数字 15px/600（等宽数字）+ 标签 11px 淡灰，读起来是「2 成员 11 消息 8 任务」。
- **依赖图行**去掉描边，改成两列对齐 + 等宽数字，只有悬停时给一层 `rgba(128,128,128,0.10)` 浅底。
- **颜色纪律**：箭头、计数、时间线竖条一律中性灰，页面上的彩色只留给「人」和「状态」。

颜色从哪来（§5.59）：每个角色在自己的 `role.json` 里有一个 `color` 字段，值是固定十个深色里的一个。
老角色在插件读盘时自动补写一个（`RoleStore.colored` 里能看到补了哪些），新建角色在保存时自动分配，
**界面上不展示、也不给改**。Lead 固定深紫 `#6B21A8`（这个紫**不在**角色调色板里，所以角色不会跟 Lead 撞色）；
成员名对回角色表（`roles[].memberName`）取色，
对不上（手工起的成员名、角色表还没回来）就按名字稳定散列，绝不会没有颜色。


## §5.62 第三轮微调（用户 2026-10-13）

1. **页头第一行不再标注日志范围**：`2 成员 11 消息 8 任务` 后面那截「整份日志」去掉；
   只有真的没读完时才会出现「（历史未载完）」——那是提示，不是标注。
2. **依赖图两行彻底无底色**：常态透明，悬停也不再上灰（`graphRowHover` 已删除）。
3. **统计周期那行**：删掉「统计周期」四个字，两个下拉框之间只留一个短横线 `-`。
4. **统计行与周期条的框**（同日反复了两轮，最终版）：框套在**每个统计项**上（`2 成员` / `11 消息` / `8 任务`
   各一个亮灰小框 `1px solid rgba(128,128,128,0.28)` + 8px 圆角 + `2px 8px` 内边距），整行本身没有框，字号不变；
   周期条**无框无底色**，灰色全部下放到两个下拉框自身：白底 + 亮灰细边（同一档 `rgba(128,128,128,0.28)`）。


### §5.63 两个下拉框改成自绘（同日，回答「为啥点击再取消后框框不见了」）

问题是「半吊子」造成的：控件还是**原生外观**（`appearance: auto`），浏览器点它时自己画焦点外观，
把上面那圈 **1px / 0.28** 的极淡灰边盖掉了 —— 边没变，只是看不见了。别的插件和 dsh 核心不受影响，
因为它们要么用自绘按钮（模型/权限选择器是 `<button aria-haspopup="menu">`），
要么走宿主自带的 `.dshvu_select{appearance:none; padding-right:28px;…}`，从来没有"自己画的淡边"可丢。

改法跟宿主对齐（`src\client\styles.js` 的 `chatStyles.select` + `src\client\chat\view.js`）：

- `appearance: 'none'`（含 `WebkitAppearance`）+ `outline: 'none'`：原生外观与原生焦点圈一起关掉；
- 箭头自己画：内嵌 SVG（`backgroundImage` 的 data URI）+ `backgroundPosition: right 6px center`
  + `padding: '3px 22px 3px 8px'` 给它留位，不引任何外部图片；
- 焦点自己表示：`onFocus/onBlur` 驱动的 `selectStyle(key)` 把边框从 `rgba(128,128,128,0.28)` 加深到 `0.6`。

真机取数：两个 `<select>` 的 `appearance` 都是 `none`；聚焦时 `border-top-color = rgba(128, 128, 128, 0.6)`，
四个边的像素都在（左右边框 `(179,179,179)`、`outline-style: none`），Esc 取消之后边框照旧在。
`npm test` 265 pass。


### §5.64 正文改走宿主的 markdown 渲染器

正文不再自己转义显示，而是交给宿主自带的 `MarkdownText`（`@deepseek-ai/dsh-client-ui-primitives`，
官方聊天正文本就用的它，类名 `_markdown_1ypvv_5`）——**不自己写解析器，也不抄它的样式**
（`src\client\markdown.js` 只做一次 require 与空值守卫）。拿不到这个导出时退回 `<pre>` 纯文本。

踩过的坑：它是 `React.memo(...)` 的产物，`typeof` 是 **object** 不是 function，
最初用 `typeof … === 'function'` 判断，于是**永远**走回落分支、页面却毫无报错（详见
`KeyNotes\别用typeof判断组件导出.md`）。


### §5.65 派活/回报的骨架放在 `templates\通信骨架.md`

给成员与 Lead 的"照着写"骨架不再内嵌在 js 里，而是
`templates\通信骨架.md` 里的两段（锚点 `<!-- lead -->` / `<!-- teammate -->`），
`lib\team-roster.js` 启动时读一次（读不到只 warn，不拦载入）；`package.json` 的 `files` 已带上 `templates`。

**§5.65+ 措辞绑定动作**（用户追问「为啥成员的回复连标题都没有？」）：原措辞只说"照下面的形状**回报**"，
模型当成风格建议——内容照写、`##` 省掉。现改成**绑定动作**：
两段都以"派活/回报就是你发给成员的 / 发给 lead 的 **`send_message` 正文**——`##` 不许省"开头。
注：模板是 `lib\team-roster.js` **顶层 `readSkeleton()` 读一次**，改完**要重启 dsh web** 才生效（非热更新）。


### §5.66 正文空行只付一次钱 + 依赖图三条

**空行**：用户问「空这么多行，是渲染本身的问题还是 AI 当时写的问题？」——原文是标准 markdown
（块之间一个空行），问题出在渲染：宿主容器带 `white-space: pre-wrap`（把分隔换行当成一整行），
它自己的 `p` 又有 16px 上下外边距，同一个空行被算两遍（真机实测块间距 **56px**）。
修法只在自己卡片里做：`src\client\chat\view.js` 注入一小段作用域样式（`.atr-chat-md.atr-chat-md …`
重复类名提高权重），把块级元素外边距归零、列表只留 22px 左缩进，`pre-wrap` 不动（单换行折行保留）。
真机取数：段落 `margin 0px/0px`，块间距 **56px → 24px**（正好一个空行 = 一行高）。

**依赖图三条**（用户 2026-10-13）：

1. **计数夹在两个角色中间**：去掉 `count` 上的 `marginLeft: 'auto'`，渲染顺序固定为
   `名字 / 计数 / 名字`；两个方向**永远都报数字**（用户随后补一句「没有消息就是 0，对称懂吗」）——
   单向的那行写 `@0 ⇄ @1`，不再省略成 `→ @n`。数字跟着显示顺序走（左数字 = 左→右）。
2. **角色胶囊等宽**：`graphChipStyle` 按这一屏出现过的名字估一个统一宽度
   （中日韩字符 13px、其他 7.5px，再加 20px 内边距，下限 56px），短的留白、长的不换行；
   只用于依赖图，顶部成员胶囊保持自然宽度。
3. **Lead 永远在左**：`flip = rightIsLead || (!leftIsLead && !both && pair.out === 0)`——
   只要这一对里有 Lead，Lead 一律在左边；两个数字跟着显示顺序走（左数字 = 左→右）。
   成员↔成员的对（没有 Lead）仍按「发起方在左」。

真机取数：两行为 `lead @5 ⇄ @5 devtest` 与 `lead @0 ⇄ @1 select`，三个胶囊各 73px。
`npm test` 270 pass（2026-10-13 补完下面三条修复后）。

**展开行显示完整标题**（用户同日追加 m02211/m02240「显示完整标题，把这一行占满，不用截取这么短」／
「顶到大概这个位置来」）：展开的时间线行不再按 60 字硬切，改显示消息正文的**第一行**
（`firstLine`），由 `chatStyles.tlText`（`nowrap` + `overflow:hidden` + `textOverflow:ellipsis`）
在行尾省略，完整正文挂在 `title` 上。真机取数：文字 span 1472px、所在行 1579px —— 只给右边的
`已送达` 留位置。

### §5.48 空窗口向前翻 + 合成 Lead 行 + 展开行首行（2026-10-13 修三条，`ui.test.mjs` 三组断言）

1. **合成 Lead 行不再被绕过**：Lead 是 Team 根会话，日志里没有它的 `team/member` 记录，
   所以 `roster` 会在缺行时合成一行（`[{ id: leadId, name: 'lead', phase: 'active' }, ...folded.members]`）。
   顶部名单的**可见性**（`roster.length > 0`）、**渲染**（`roster.map`）与页头「成员」计数
   （`roster.length`）现在同读 `roster`——之前这三处读 `folded.members`，合成行永远看不到，
   计数也会跟名单对不上。
2. **往前翻按实际成功段数记账**：`runScan` 的 `step` 只在 `load()` 真的返回非 `false` 时才 +1
   （`return 1 + (await step(left - 1))`），到顶或抛错都不再按满 `8` 段累加
   （累加式统一成 `rounds: current.rounds + done`）；`load()` reject 时置 `scan.error`，
   空窗口里显示一行「往前翻失败，请稍后再试。」，不再静默回到原样。
3. **展开行不吃开头空行**：`firstLine` 先剥掉开头的空白行（`/^(?:[^\S\n]*\n)+/`）再取首行，
   正文以空行开头时标题不会变成一片空白；`blockText` 的口径不变。


## 想藏掉这个 tab：「角色」页里的开关（R6）

「角色」页里有一个复选框**「在会话页签里显示「群聊」」**，写进角色文件的
`settings.hideChatTab`（默认 `false` = 显示）。翻一下**立刻**挂上 / 摘掉群聊 tab，
**不用刷新页面、也不用重启 dsh**。

机制（真实 slots 契约没有 `visible` / `enabled` 这类开关，只有 `register()` 返回的幂等 disposer，
所以「隐藏」只能是「撤掉注册」）：客户端侧在挂 tab **之前**先读 `GET /state`，
`hideChatTab === true` 就不挂；「角色」页的复选框翻转后，客户端侧立刻 `dispose()` 或重新 `register()`
那个 `conversation.view`。**读 `/state` 失败时 fail open**（照挂 tab）——多一个 tab 点一下就恢复，
而因为一次读失败把用户想要的 tab 藏起来是更糟的失败模式。

> ⚠️ `hideChatTab` 字段与 `set-hide-chat-tab` 这个 action 都在**宿主侧**，
> 所以要**重启 dsh 才生效**（重启前这个复选框是灰的，并提示「重启 dsh 后这个开关才可用」）。
> 重启之后翻开关就不再需要任何重启。

> ⚠️ **改这个文件请不要用 PowerShell。** `lib/client.js` 里全是中文串，
> `Get-Content` / `Set-Content` 的编码往返会把它们写成 `U+FFFD` + `?`（一次事故损坏了
> 61 处、82 个字符）。改它请用编辑器或 `edit` / `write` 这类按 UTF-8 读写的工具。
