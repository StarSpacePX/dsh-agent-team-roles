# 生效时机与热加载

## 对照表

| 改的东西 | 怎么生效 |
| --- | --- |
| 角色数据（名字、描述、模式、开关、技能、MCP） | 存盘即生效，不用重启 |
| 角色自己的 `AGENTS.md` | 存盘即生效，不用重启 |
| `notes.json` | 点面板上的「刷新」 |
| 插件配置（`cordis.patch.yml`） | 重启 dsh |
| `templates\通信骨架.md` | 重启 dsh |
| 界面的脚本与样式 | 刷新页面 |
| 宿主侧代码 | 重启 dsh |

## 判断宿主侧新旧

面板拿到的状态里带团队字段 = 宿主侧是新代码。

没有这个字段 = 宿主侧还是旧的，此时团队开关和群聊显示开关都是灰的，提示重启 dsh 后可用。

## 存盘后的状态

写配置只落 JSON，不等着重建。面板上显示「已存盘 · 下次用到该角色时生效」。

这行字的意思是：文件已经写好了，下次要用这个角色时会带上新配置。正在跑的成员不受影响，新开的会话才用新配置。

面板后台大约 200 毫秒后合并一次重建。成员创建的那一刻如果角色还没挂上，会在选角色之前补挂。

## 刷新按钮

「刷新」做四件事：

1. 重读磁盘上的角色文件。
2. 重读这个部署的模式名册。
3. 重读组合清单。
4. 重新同步面板状态。

手改了 `role.json` 或 `notes.json` 之后点一下即可，不用重启。

## 开关的节奏

面板上的行开关和技能勾选，一次手势发一条请求，连点多下会合并成一条，间隔约 120 毫秒。

失败提示显示 8 秒后自己消失，中途操作成功会立刻清掉。

## 冷启动

dsh 刚起来时，第一次读面板状态要等一次部署组合清单，大约 4 秒，之后都是毫秒级。插件启动 2 秒后自己预热一次，所以通常你点进去时已经好了。
