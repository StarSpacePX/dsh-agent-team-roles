# 边界与扩展点

## 边界

插件只延伸 dsh 已经公开的接口，不改核心。

用到的地方：

| 能力 | 用法 |
| --- | --- |
| 注册角色 | 用预设注册接口，把角色登记成一个预设 |
| 选角色 | 用预设选择接口指定成员用哪个角色 |
| 写名册 | 用系统提示注入接口，只注入到 Lead 的会话 |
| 拦截创建 | 包一层创建与恢复调用，只改里面的绑定那一步 |

创建与恢复的包装只改写绑定参数，其余参数原样展开交给原实现。下面四种情况原样透传，不做任何处理：

1. 参数形状不对。
2. 成员绑定关着。
3. 不是被委派出去的子会话。
4. 插件已经卸载。

绑定失败只记日志，不会把成员降级成父角色，也不影响创建结果。

插件不改 dsh 核心，所以升级 dsh 不会留下插件写进去的东西。

用户能感知的影响只有一条：成员创建失败后，这个名字会被永久占用。

- 名字在创建之前就登记了，失败后不会回滚。
- 这是 dsh 本体的行为，插件改不了。
- 缓解办法：控制并发，一次只建一个成员；失败了不要改个名字重试，先查为什么失败。

## 已知限制

| 限制 | 说明 |
| --- | --- |
| 没有 loop 行 | 角色不能自带 loop 行，所以没有「角色工作目录」这个设置。任务在哪个目录跑，新建任务时选 |
| 没有逐行配置编辑器 | 面板只做开关。行上的配置原样带过来，鼠标悬停能看到 |
| 能力行跟着部署走 | 角色能用哪些行来自部署当前的预设，dsh 升级后这里跟着变 |
| 极简模式读不到角色规则 | 极简模式没有规则行，这个模式下角色自己的 `AGENTS.md` 不生效 |
| 成员改名不影响已建的 | 角色改名后，已经建出来的成员不会跟着改 |
| MCP 与工具开关是过滤 | 是可见性过滤，不是卸载 |
| 成员之间看不见彼此 | 只有 Lead 有名册，成员之间靠 Lead 转 |
| 并发创建没有互斥 | 插件不拦同时创建，名字占用只能靠控制并发避开 |
| 继承上下文的成员可能在老会话里建不出来 | 成因在 dsh 本体的 seed 校验：`spawn_teammate` 选「继承上下文」（fork）时，父会话前几条事件要当子会话的 seed 再过一遍信封校验，老会话有概率报 `seed event at index N has an invalid event envelope`。同一个会话里失败过的名字会一直失败 |
| 上面这条的规避 | 换新会话创建，或成员改选「不继承上下文」（fresh）。fork 失败不要改名重试，先开新会话 |
