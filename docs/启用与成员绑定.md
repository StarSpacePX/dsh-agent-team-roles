# 启用与成员绑定

## 启用智能体团队

设置 → 插件 → 智能体团队，顶部一个复选框「启用智能体团队」。

打开它同时做两件事：

1. 让 dsh 选上团队组合包。
2. 打开成员绑定。

关掉两个一起关。

改完看结果提示：

| 结果 | 提示 |
| --- | --- |
| 立即生效 | 「已生效」 |
| 要重启 | 「已保存，重启 dsh 后生效」 |

开关灰掉、并给出原因的情况：

| 情况 | 表现 |
| --- | --- |
| 没有插件管理器 | 开关灰，显示原因 |
| 安装里没有这个组合包 | 开关灰，显示原因 |
| 宿主侧还是旧代码 | 开关灰，提示重启 dsh 后可用 |

判断宿主侧新旧：面板拿到的状态里有团队字段就是新代码。

## 成员绑定

成员创建时自动绑到同名角色。成员名就是角色 id 去掉前缀。

规则：

1. 只处理被委派出去的子会话。主会话、普通会话不管。
2. 匹配顺序：先按成员名找角色，找不到再按委派描述找。
3. 两边都没匹配到就什么都不做，成员照常创建。
4. 绑定失败只记日志。不回退成父角色，也不影响创建结果。

普通 `subagent` 如果描述能对上角色名，也会被认领。

界面**没有**单独的成员绑定开关：绑定跟「启用智能体团队」联动，开团队就开绑定，关团队就关绑定。

## 强制绑定

插件配置 `bindMembers: true` 可以强制打开绑定，部署级生效，改配置要重启 dsh。

这时面板会提示「插件配置里的 bindMembers 已强制打开成员绑定，这个开关关掉它也不受影响」，
关掉「启用智能体团队」也仍有绑定。

## 注意

成员创建失败后，这个名字会被 dsh 永久占用，不能再建同名成员，也改不了名。

缓解办法：一次只建一个成员，成功后再建下一个，不要并发创建。
