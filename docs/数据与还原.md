# 数据与还原

## 写配置不再重建：JSON 即元数据，用到才挂载（§5.54，用户 m17251）

用户的原话是：「我勾选一个技能，就是对 json 配置改一次，需要什么玩意增量什么玩意全局？」

改之前的事实：**勾一个技能 = 10778 ms**（同值重发的 no-op 也一样，GUI 实测、HTTP 200、回包 48775 B）。
原因不是前端（`lib/client.js` 里 `SWITCH_BURST_MS = 120` 的合并已经把连点压成一次 POST），
而是 `mutate` 里那句「写完就 `await sync(presets)`」：`sync()` 无条件把**每个**角色
dispose + 重新 register，每次 register 又是 31 行的一棵树（`…dsh-agent-preset-registry/lib/index.js:500-545`）
+ 一次全量审计（`presets.list()` → `…dsh-agent-preset-registry/lib/index.js:557-568` 里 `await owner.loader.await()`，
等的是**整个宿主 Loader**）。所以角色的挂载被拆成三件事，各归各位：

- **写**（勾选、开关行、改模式、删角色）：只落 JSON + 内存里的期望定义 + 标 dirty，
  **不 register、不 list**，回包毫秒级返回。不再存在的角色当场卸掉，改过的角色只记进
  `deferred`（`/state` 里看得见，GUI 显示「已存盘 · 下次用到该角色时生效」）。
- **构建**：惰性。启动时只把「主会话可能选到的角色预设」注册一次；成员创建窗口里
  `ensureRegistered(roleId)` 在 `select()` 之前补挂（§5.53 那条路径），用完即算数。
  写完之后的后台重建只是**尽力**（200 ms 去抖），谁都不等它。
- **读**：`buildState()` 不再问注册表；`registry` / `broken` 来自挂载后刷新的健康缓存，
  别人的 preset 坏了不会出现在本插件面板里。

第二刀砍的是**读**：`/state` 自己还要 1311–1919 ms。分段计时（临时 `console.log`，见
`KeyNotes\插件里的logger.info看不到先用console.log.md`）显示 `team=1038–2184 ms`，
其余 `template/modes/deployment/mcp/skills/notes` 合计 20–200 ms —— 慢的是
`readTeam()` 里那次跨 Remote 的 `pluginManager.listBundles()`，它那一侧是**同步**读盘
（profile 清单 + 安装锚点 + 每个组合包的 `package.json`）。它回答的是**部署**的属性，而换组合包
本来就得重启 dsh，所以：缓存 60 秒 + 过期只**后台续读**（stale-while-revalidate，续读排到
250 ms 之后，不在回包路径上）+ 我们翻开关时当场改缓存里那一位（不再为一次确认读一遍 1.2 秒的清单）
+ 只有「重载」这个明确要求重读的动作才真的等一次。

| 动作 | 改前 | 改后（3099 真机，`performance.now()`） |
| --- | --- | --- |
| 勾一个技能（真改 / 同值重发） | 10778 ms | 161 ms / 161 ms |
| 面板读状态（缓存热） | 1311–1919 ms | 69–121 ms |
| 面板读状态（缓存过期） | 同上 | 86 ms（旧值；250 ms 后后台换新值） |
| 「重载」 | 1311 ms+ | 仍然真读一次（明确要求） |

- **测试**：`tests/plugin/team-and-config.test.mjs` 的 `§5.54` 区间 —— 写配置回包时 `listCalls` / `registerCalls`
  一个都不涨、`deferred` 里有那个角色、创建成员时补挂、`sync` 不动没变的角色、
  连续两次 `/state` 只问一次部署、翻开关**不**重读清单而「重载」重读。
- **数字怎么复现**：`dsh --profile web --port 3099 --no-open`（第二实例），页面里
  `fetch('/api/dsh-agent-team-roles/command', { action: 'set-skills', … })` 用 `performance.now()` 计时。
  注意：宿主半的改动**必须重启 dsh** 才生效。

## 数据放在哪

**一个角色 = 一个目录**，目录名就是角色 id（前缀由插件加，见
[配置项](配置项.md)）：

```
<DSH_HOME 或 ~/.dsh>/agent-team-roles/
  roles.json              ← 只剩插件级设置：{ "version": 2, "settings": { … } }
  notes.json              ← 可选：面板上那些说明文字（见「说明书是数据」）
  team-architect/
    role.json             ← 这个角色的全部开关与配置
    AGENTS.md             ← 这个角色自己的规则文件（新建时从主会话复制一份）
```

角色目录**就是这个角色所有文件的落脚点**：`role.json`（开关与配置）和它自己的 `AGENTS.md` 都在里面。
界面上**只显示这一个路径**（角色目录），没有输入框（用户 m06726「把这个路径和成一个，不需要到文件级别」、
m06762「只是显示一个路径，不改路径」）。

**角色的 `AGENTS.md` 是怎么被读到的**：不是靠「让它在自己目录里运行」（任务在哪个目录跑由新建任务时选择决定，
预设改不了 —— 见「为什么没有 loop 行」），而是把角色 preset 里那个**已有的** `agent-instructions` 行加一个
`config.dshHome = <角色目录>`。`dsh-agent-instructions` 会**无条件**把 `join(dshHome, 'AGENTS.md')` 加进候选，
于是该角色无论 cwd 在哪都先读 `<角色目录>/AGENTS.md`，项目自己的 `AGENTS.md` 仍在其后加载（角色规则优先、项目规则补充）。
实测（真实包）：`discoverBaselineInstructionFiles({ cwd, dshHome: <角色目录>, maxBytes })` 返回
`<角色目录>/AGENTS.md`（displayPath `$DSH_HOME/AGENTS.md`）+ 项目的 `AGENTS.md`。用户若自己在该行写了 `dshHome`（含 `null`），以用户的为准。

```json
{
  "version": 2,
  "id": "team-architect",
  "name": "架构师",
  "description": "以 standard 为模板的角色",
  "order": 10,
  "overrides": {
    "tool-bash": { "disabled": false },
    "tool-web": { "config": { "fetch": false } }
  },
  "capabilities": {
    "mcp": { "deny": ["github"] }
  },
  "agentsMd": { "source": "<主会话的 AGENTS.md 路径>", "copiedAt": "2026-09-28T00:00:00.000Z" }
}
```

`overrides` 与 `capabilities` 是**两张分开的表**：前者的键是快照里的行 id，后者只装
「快照里没有行的能力」（现在只剩 MCP 隐藏名单一项）。混在一起的话，一个打错的行 id
就没法和一个合法的能力键区分了。

> 早期（§5.29）的 `capabilities` 里还有一块 `loop: { enabled, cwd, maxParallelToolCalls }`。
> §5.30 之后它**已被退休**：读到旧角色文件里的 `loop` 块会直接丢掉（不会报错，也不会复活），
> 因为角色根本不能再携带 `agent-loop` 行 —— 原因见「为什么没有 loop 行」。

组合后的 preset 每次都由快照 + `overrides` 现算，所以**dsh 升级后角色的能力行会跟着升级**，
而角色自己的决定保持不变。

`overrides.<rowId>.config` 是**叠加**在模板 config 上的补丁；把某个键写成 `null` 表示
「把模板里的这个键删掉」。`agentsMd` 只是「这个文件从哪来」的元数据（界面显示「新建时复制自 …」），
删掉它不会删文件。

`createdAt` / `updatedAt` 由插件在写入时盖上，读盘时原样保留。早期版本会在读盘时丢掉这两个
字段，于是任何一次保存都会把时间戳抹掉（文件不是 fixpoint），已修并加了回归测试。

角色文件与快照都是**不带 BOM 的 UTF-8**；但读取侧容忍开头的 BOM（`lib/template.js` 的
`parseSnapshot()`），因为 `Set-Content -Encoding UTF8` 这类写法会加上它，而 `JSON.parse` 撞上它只会
说 `Unexpected token '\uFEFF'`——看起来像文件损坏，其实只是多了三个字节。

### 从旧版（单文件 `roles.json`）迁移

索引里如果还有旧版那种内联的 `roles[]`，**第一次加载时会自动迁移**：每个角色写进自己的目录，
全部成功之后索引才被改写成 v2。迁移只能搬数据，所以宿主半还会补一步——给这个角色也复制一份
`AGENTS.md`。结果：迁移过来的老角色和界面上新建的角色**形态完全一致**。
（更早的 `capabilities.loop` 块会在这一步被丢掉，见上文。）

同一个目录里的 `role.json` 如果坏了、或者它的 `id` 和目录名对不上，只有**那一个**角色会被标成
`invalid`（界面显示「无效」），不会让整份数据读不出来。

### 四层还原

| 层 | 界面上的按钮 | 行为 |
|---|---|---|
| 建角色 | 新建角色 | 建目录 → 复制主会话的 `AGENTS.md` → 写 `role.json`（`overrides` 空、`capabilities.mcp.deny` 空）|
| 角色级还原 | 全部还原（保留名字与 AGENTS.md） | `overrides` 清空、`capabilities` 回默认；**保留** 名字/描述/order，**不碰** `AGENTS.md` 文件；文件的接入是派生的，还原后仍然接得上 |
| 逐项还原 | AGENTS.md 面板 / 行表各一个「还原默认」 | 只重写那一大项：AGENTS.md **重新从主会话复制一份**并清掉该行被改过的键；行表 = 回到**这个角色当前模式**模板的样子（含 MCP 勾选）|
| 删除角色 | 删除角色 | 删掉**整个角色目录**：`role.json` 与 `AGENTS.md` 一起没 |
