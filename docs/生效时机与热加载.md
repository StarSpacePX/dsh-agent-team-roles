# 生效时机与热加载

## 生效时机

`agentPresets.register()` 在 mount 时就固定了组合，所以改完角色必须**先卸载再注册**。
这个「拆掉再挂上」就是需求里说的**下个热更新生效**：`save()` 之后插件立刻 reconcile，
不需要重启 dsh。

⚠️ 但**插件自己的代码**分两半：客户端半（`lib/client.js`，包括 `@` 源）刷新页面就生效；
宿主半（`lib/index.js`、`lib/host/`、`lib/team-roster.js`、`lib/team-watch.js`，包括 `team-send` 这个 action）
是 dsh 启动时加载的，**必须重启一次 dsh**。重启前如果客户端先发了 `team-send`，
老宿主半会把它当成未知 action 拒掉。

## 热加载的实际行为（2026-09-27 实测）

| 改什么 | 怎么生效 |
| --- | --- |
| 角色数据（`<id>/role.json`） | **立即** —— 插件对每个变化的角色先 `unregister` 再 `register` |
| 客户端半边 `lib/client.js` | **刷新页面即可**。bundle 由 `GET /plugins/??<包名>/client.js&rev=<hash>` 现读磁盘，改文件会让 `rev` 变，刷新就拿到新代码 |
| 宿主半边 `lib/index.js` / `lib/host/` 等 | **不改则已，改了必须重启 dsh** —— Node 的 ESM 模块缓存不会因文件变化重新编译，已装载的插件继续跑旧代码 |

宿主半边的逻辑因此只靠 `node --test` 覆盖，端到端验证需要重启 dsh。
