# DSH 插件发布流程与开源仓库标准调研

调研对象：把 `dsh-agent-team-roles` 发布到 DSH 插件市场（dshmarket / 官方 Discover）需要什么。
数据实测时间：2026-11-05，数据源原文见各条 URL。

## 一、市场发布

**两条独立通道**，别混为一谈：

1. **awesome-dsh-plugin 列表**（第三方，dshmarket 的数据源）：`https://awesome-dsh-plugin.com/plugins.json`，实测 8655 条，`updated: 2026-11-03`，仓库 `https://github.com/awesome-dsh-plugin/awesome-dsh-plugin`。
2. **DSH 官方「发现」索引**（官方内置，dsh 0.2.1+）：format=1 的 JSON，官方文档 `https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/plugin-market.zh.md`。

### 1.1 plugins.json 条目 schema

顶层键：`name` / `url` / `source` / `updated` / `count` / `categories` / `plugins`。单条字段（实测全量统计，括号内为出现次数）：

| 字段 | 说明 | 作者要自己写 |
|---|---|---|
| `name` `owner` `url` `page` | 插件名、作者、仓库、市场详情页 | 由 url 推导 |
| `category` `description{en,zh}` | 分类、双语一句话描述 | **是** |
| `icon`（605）、`tarball`（1194）、`screenshots`（2015） | 可选 | 是 |
| `npm` `version` `stars` `downloads` `downloadsStart/End/CheckedAt` | 采集而来 | 否 |
| `capabilities` `capabilityRedLines` `capabilityCheckedAt`（7955） | 脚本审计的能力标签（如 shell / fs-write / network） | 否 |
| `install`（8655/8655 全有） | 安装命令，统一形如 `dsh plugin --profile web add <spec>` | 自动生成 |
| `added` | 收录日期 | 否 |

即：投稿人只写 `url` / `name` / `category` / `description` / `icon` / `tarball`，其余全自动。

| 插件 | npm 字段 | install 实际值 |
|---|---|---|
| `ui-beep`（xain） | `@xain_npm/dsh-client-ui-beep` 0.6.2 | `dsh plugin --profile web add @xain_npm/dsh-client-ui-beep` |

### 1.3 收录入口与步骤（确切 URL）

**网址：** `https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pulls`，指南原文 `https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md`。

- 提 PR 新增 **1 个文件**：`data/plugins/<owner>__<repo>.yml`（不是网页表单，不是 CLI，README 是脚本生成的，禁止手改）。
- yml 内容：`url:`（必填，与仓库完全一致）、`name: owner/repo`、`category:`、`description.en:`（**唯一必填描述**，`zh` 可选，维护者会补）、可选 `icon:`、`tarball:`。
- `description` 含 `: ` 必须加引号，否则 YAML 解析失败。
- 一个 PR 最多 3 条；仓库需**创建满 1 天**（CI 自动查）；仓库加 `dsh-plugin` topic；代码必须真实可用，描述必须与代码一致（会人工核对）。
- CI 依次查：条目数 → 仓库 `package.json` 的 `dsh.bundle`（只有 `dsh.client` 直接失败）→ 仓库年龄 → awesome-lint 与站点构建。
- 分类取值（23 个）：`agi ui usage theme model identity session memory tools wsl browser vision voice docs skill workflow git notify dev security remote market fun`。
- 合并后网站自动重建，无需再操作。

### 1.4 官方「发现」索引（format 1）

- 官方文档同上；示例源 `https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json`（npm 包 `dsh-plugin-catalog`，repository 指回 awesome 仓库）。
- 实测 `https://awesome-dsh-plugin.com/index.json`：`format: 1`、4386 条 —— 恰好等于 plugins.json 中 `npm != null` 的 4386 条。**未发 npm 的 4269 条不会进官方索引。**
- 索引必填：`format`（=1）、`plugins[]`；插件必填 `name`（npm 包名，索引内唯一）、`versions[]`；版本必填 `version`（精确 SemVer）、`publishTimestamp`（Unix 秒）、`source`。
- `source` 两种：`{"type":"npm","registry"?:url}` 或 `{"type":"git","url":https-url,"commit":40位SHA,"path"?:目录}`。
- 可选：`title`/`description`（LocalizedText，对象必须含 `en`）、`icon`、`author`、`homepage`、`repository{url,directory}`、`metadata.category/labels/sortKeys`、`engines.dsh`。
- DSH 安装规则：npm 版本装成 `name@version`；git 版本装成 `git+<url>.git#<commit>`（子目录追加 `&path:/<path>`）。
- 官方参考生成器 `apps/plugin-market-generator`：输入纯文本列表（npm 包名或 https 仓库 URL）→ 输出 `index.json` + `icons/`。

### 1.5 结论：npm 是不是必需

**不是必需，但强烈建议。** 证据链：

- `install` 字段统一是 `dsh plugin --profile web add <spec>`，spec 可以是包名、`github:owner/repo`、或 `.tgz` URL，三种都被收录。
- 但官方 Discover 索引只列 npm 版本（4386/8655），不发 npm 就等于放弃官方发现页。
- 官方文档明确：git 安装拉的是**源码不是构建产物**，作者要写自包含 `prepare`，用户还要在 profile 的 `pnpm-workspace.yaml` 里写 `allowBuilds` 授权构建；发 npm 或发 tarball 都免这一步（`docs/user/develop/basic/publish.zh.md`）。

## 二、开源仓库标准

参考仓库：`https://github.com/MichengAI/dsh-skills-manager`（Apache-2.0，462 star，default branch `master`，npm `@michengai/dsh-skills-manager` 1.2.29）。

### 2.1 目录约定（实测根目录）

```
package.json  cordis.patch.yml  LICENSE  README.md  README.zh-CN.md
CHANGELOG.md  CHANGELOG.zh-CN.md  src/  lib/  locale/  assets/
scripts/  test/  tsconfig.json  pnpm-workspace.yaml  pnpm-lock.yaml  .github/workflows/
```

要点：`src/` 源码 + `lib/` 构建产物**都提交**（`lib` 进 npm 包，`src` 便于审计）；测试在 `test/`；工作流在 `.github/workflows/`。

### 2.2 package.json 必备字段（照抄这套）

- 身份：`name`（scoped，如 `@michengai/dsh-skills-manager`）、`version`、`description`（中英双语的单行，用 `·` 分隔）、`license`、`repository`、`bugs`、`homepage`、`keywords`（必含 `dsh-plugin`）、`engines`（`node` + `dsh` 双范围，如 `"dsh": ">=0.2.0-rc.1 <0.3.0-0"`）。
- 入口：`type: "module"`、`main`、`exports`（至少 `"."`、`"./client"`、`"./package.json"`）。
- 发布：`files` 白名单（`lib` `locale` `assets` `cordis.patch.yml` `CHANGELOG*.md`）、`publishConfig{registry, access:"public"}`、`scripts.prepack`（构建）、`scripts.prepublishOnly`（跑 verify）。
- 依赖：官方 `@deepseek-ai/*` 同时进 `peerDependencies` 与 `devDependencies`；peer 范围**必须带显式预发布分支**，否则静默排除所有 rc 版本（贡献指南原文举例：`">=0.0.1-rc.1 <0.1.0 || >=0.1.0-rc.1 <0.2.0-0"`）。
- 可选：`icon`（仓库内相对路径，如 `assets/icon.svg`）；`screenshots.json`（放 package.json 旁，1–8 张仓库内图片，市场详情页 AppStore 式展示）。

### 2.3 `dsh` 字段与 cordis.patch.yml 规范

官方文档 `docs/user/develop/basic/publish.zh.md`：

- `dsh.bundle.patch` = 相对路径，指向本包的 patch 文件（也接受有序文件数组）——**这是「能被 `dsh plugin add` 安装」的唯一开关**，缺了只当普通依赖并告警。
- patch 文件是 patch 条目 YAML 数组，`insert` 行按**包名**引用自己，不要用相对源码路径：

```yaml
- insert:
    - id: skills-manager
      name: '@michengai/dsh-skills-manager'
```

- `dsh.client`（官方 `docs/subsystems/client-modules.zh.md`）：声明 `platform: 'web'`、可选 `inject`（依赖的其他 client 包名边）、可选 `immediately`，并在 `exports["./client"]` 导出已构建的浏览器 bundle；宿主扫 Loader entry 里声明了 `dsh.client` 的包，组合成 `window.__DSH_BOOT__` 图。
- 层顺序（后应用者按行胜出、patch 替换整行 config 而非深合并）：各 bundle patch（按 bundles 列表顺序）→ profile 自己的 `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → 各 `--patch`。

### 2.4 README / LICENSE / CHANGELOG / CI

- README：`README.md`（英文）+ `README.zh-CN.md`（中文）双语互链；顶部 banner 图 + 徽章（License、npm 版本、npm 下载量、DSH 支持版本）；正文对标「社区插件、非官方产品」的免责声明；文内链 Changelog 与 LICENSE。
- LICENSE：Apache-2.0（文件在根，README 徽章指回）。
- CHANGELOG：中英各一份（`CHANGELOG.md` / `CHANGELOG.zh-CN.md`），`## <version> - <YYYY-MM-DD>` 分节，条目按主题一行为一条。
- CI：`.github/workflows/` 4 个文件（`verify.yml` `compatibility.yml` `publish.yml` `release.yml`）；`publish.yml` 由 `v*` tag 触发，`permissions: id-token: write`（npm trusted publisher / OIDC 发布，无 `NODE_AUTH_TOKEN`），发布前校验 tag 必须等于 `v<package.json version>`，`npm publish` 后再由 `release.yml` 从 CHANGELOG 抽双语发行说明建 Release。

## 三、npm 发布

- 名字可用性（2026-11-05 实测 registry）：`dsh-agent-team-roles` → HTTP 404 **未占用**；`@starspace/dsh-agent-team-roles` → HTTP 404 **未占用**。
- 先去 `private: true`，否则 `npm publish` 直接拒绝。
- `files` 白名单决定包内容；`npm pack --dry-run --json` 自查（skills-manager 把它固化成 `pack:check` 脚本）。
- `publishConfig.access: "public"`：scoped 包必须写，否则默认私有；unscoped 包默认就是 public。
- `prepublishOnly` / `prepack`：保证发布前构建出 `lib/`，否则用户装到没有产物的包。
- 官方 `@deepseek-ai/*` 一律 `peerDependencies`（与宿主共享实例），版本范围带预发布分支。
- 参考文档：`https://docs.npmjs.com/cli/v10/configuring-npm/package-json#files`、`https://docs.npmjs.com/cli/v10/using-npm/developers`、`https://docs.npmjs.com/cli/v10/commands/npm-publish`、`https://docs.npmjs.com/trusted-publishers`。
- 备选（不发 npm）：发 GitHub Release tarball 并在市场条目写 `tarball:`；或让用户 `dsh plugin add github:owner/repo` + `allowBuilds` 授权。
