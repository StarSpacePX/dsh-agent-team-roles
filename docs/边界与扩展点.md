# 边界与扩展点

## 边界：只延伸官方接口，不改核心

**Agent Teams 运行时是 dsh 自带的**（`@deepseek-ai/dsh-experimental-agent-team-profile`）。本插件只在它上面延伸，
不改它一个字节。三栏账本：

**① 走官方公开扩展点**

| 动作 | 位置 |
|---|---|
| 拿官方服务 | `lib/host/bind.js:169` `ctx.inject(['agentPresets','agents'], …)` |
| 注册角色 | `ctx.agentPresets.register(definition)`（角色 = preset） |
| 选角色 | `lib/host/bind.js:209` `await service.select(child, role.id)`——`agentPresets.select` 是唯一公开入口 |
| 注入名册 | `lib/team-roster.js:214` 的 `prompt.context`（order 130） |
| 插入点 | `lib/host/bind.js:242` 用 `create`/`resume` 请求对象里**本来就有的** `setup` 回调 |

**② 包了一层 `agents.create` / `agents.resume`（`lib/host/bind.js:256-297`）——严格说是猴补丁，但只覆盖配置**

- `:240-253` 返回 `{ ...params, setup: … }`：**其余字段原样展开**，改写的只有 `setup`（先跑调用方自己的
  setup，再 `bindChild`）。
- `:269-271` 无论走哪条路，最后都是 `original.call(...)`——干活的始终是官方原实现。
- 四种情况**原样透传，绝不静默改写**：`:229` 参数形状不对、`:230` 绑定开关关着、`:238` 不是被委派的子
  （无 `parentAgent`）、`:283-285` 已卸载。
- 绑定失败只 `logger.warn`（`:249-251`），**不退化成父角色**——角色含工具范围与权限模式，静默降级是
  安全问题。

**③ 一个字节都没碰**

官方 `TeamRoster` / `journal` / `spawnAdmitted` / 「登记与创建」的事务 / 子代理池 `continuation-activation` /
官方工具注册 / `team:policy` 系统提示词 / 官方面板（`dsh-experimental-client-ui-agent-team`）的投影。

**为什么这一栏重要**：正因为 ③ 没碰，官方那条「创建失败后成员名永久占用」（内部 G-harness 提案的 G1/G2）**本插件修不了**——它在 `dsh-experimental-agent-team/lib/index.js:563`（查重只看 name、不看 phase）
与 `:584-597`（失败只改写 phase、不回滚登记）。插件侧能做的只有：开团队前控制并发、创建失败后别改名重试。
要根治必须提上游。


## 为什么没有 loop 行（§5.30）

用户当初要的是「loop 加路径选择」，实现时也确实写出了一条 `agent-team-loop` 行。**但它在真机上走不通**，
两堵墙：

1. **服务名撞名**：`agent-loop` 注册的是全局单例服务 `agentLoop`（`dsh-agent-loop\lib\index.js:1508`
   `class AgentLoop extends Service`、`:1537` `super(ctx, "agentLoop")`），
   而 `dsh-agent-preset-registry\lib\types\mount.js:241` 拒绝「preset 里携带不在 isolate realm 里的服务」
   （`throw new Error('Preset services require isolate realms: …')`）。→ 包一层
   `{ name: 'cordis:group', group: true, isolate: { agentLoop: true }, config: [ … ] }` 可以解决**这一条**。
2. **agent 工厂名额只有一个** ⭐：`dsh-agent\lib\types\index.js:427-433` 的 `setFactory(factory)`
   在已有工厂时直接抛 `an agent factory is already registered`。`agent-loop` 是部署级单例、早就占掉了名额，
   **isolate realm 隔离不了它**。实测现象：`registry` 里出现
   `broken: "agent-loop (@deepseek-ai/dsh-agent-loop): an agent factory is already registered"`，
   该角色在新建任务页的模式列表里**彻底消失**。

旁证：官方四个 shipped preset（`standard` / `ptc` / `minimal` / `cordis`）里**没有任何一行**是 loop 或 mcp 客户端；
`dsh-agent-preset-registry\lib\types\definition.d.ts:4-13` 的 `PresetDefinition` 里**没有 cwd 字段**。
任务在哪个目录跑由**会话表头**决定（`dsh-api-session-controller\lib\index.js:253` `ensureSession(sessionId, cwd, …)`，
`:272-273` 的 `ApiSessionCwdConflict` 断言），预设改不了。

所以现在的做法是：**删掉 `buildLoopRow()` / `set-loop` / `capabilities.loop`**，
面板退化成只读的「**角色工作目录**」（显示角色目录 + 一句说明：任务目录由新建任务时选择决定；
部署的 `agent-loop` 是全局的，它的 `maxParallelToolCalls` 不是角色能配的）。
角色的 `AGENTS.md` 改由 `agent-instructions` 行的 `dshHome` 接入——**这才是「不填路径也能读到角色规则」的正解**。

> `lib/template/deployment.json` 快照与 `tools/extract-deployment.mjs --check` **保留**：
> 它现在只用于面板上那句只读说明（`/state` 的 `workdir` 段），不再参与任何角色组合。

> ⚠️ MCP 这一类是**宿主侧**的功能，改动**要重启 dsh 才生效**。重启前，MCP 面板会渲染成空、
> 开关点了也只会得到「未知 action」——界面如实呈现，不假装能点。
> 宿主侧的 MCP 网关挂载点同样要重启才会执行 `tools.restrict`，所以就算手工把 `deny` 写进角色文件，
> 重启前那个 server 的工具**依然看得见**。
