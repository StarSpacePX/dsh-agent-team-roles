# 日志

## 走哪个通道

插件**不自己写文件日志**，走 dsh 的常规日志通道：

```js
// lib/index.js:81
const logger = typeof ctx.logger === 'function' ? ctx.logger('agent-team-roles') : console
```

- logger 名固定为 **`agent-team-roles`**，dsh 的日志输出里带这个名字的就是本插件打的。
- `DSH_HOME` 下**没有**本插件自己的日志目录，这是**正常现象**，不是装坏了。
- 没有 `ctx.logger` 时的兜底是 `console`（只在测试/无宿主环境里会走到）。

## 怎么排查

1. **先看 dsh 启动日志里 `agent-team-roles` 前缀的行**：插件装上没装、`apply` 有没有跑、配置归一化的结果在这里。
2. **界面上「已生效 / 已保存，重启 dsh 后生效」**是插件如实回报的结果，别只看日志猜。
3. 宿主侧改动（注册角色、绑定成员、写角色文件）要**重启 dsh** 才在进程里体现；热加载只覆盖客户端侧。
4. 数据对不对直接看 `<DSH_HOME>/agent-team-roles/` 下的 `roles.json` 与每个角色的 `role.json` / `AGENTS.md`。

## 禁止

- **不准加临时调试通道 / 后门**：不写隐藏的调试文件、不开未声明的调试端点、不把调试输出塞进角色数据目录。
- 需要临时观察时用 `logger`，排查完删掉。
