# 角色依赖图

## 角色依赖图

消息流上方还有一张**依赖图**：把消息按方向聚合成 `A → B` 这样的箭头，每行右侧标注
这个方向的 **@ 次数**；**点一下箭头就展开多行时间流**（每行一个时刻，精确到秒，带该次
消息的正文摘要与送达状态）。

箭头对是 `foldPairs()` 按消息首次出现的顺序算出来的。统计口径可以收窄：两个下拉框分别
选周期的**起点 @** 与**终点 @**（选项是 `第 N 次 @ · HH:MM:SS`，只列 Lead 发出的 @），
**默认就是「第一次 @ → 最新」**，点「恢复默认」回到全量。周期一旦选定，**消息流和依赖图
一起跟着收窄**。

Lead 的身份来自 `TeamId`（= 本会话 id）：日志里的 `team/member` 只记 teammate，
Lead 自己不写这条事件，所以 roster 会补一行合成的 `lead`。

**这个运行时默认是关的。** 没开「智能体团队」时 tab 显示一段空态说明与开启方式
（设置 → 插件 →「智能体团队」，或
`dsh plugin --profile web add @deepseek-ai/dsh-experimental-agent-team-profile`，
开启后需要重启 dsh）。开着但没有 team 事件的普通会话同样是空态。

> 更细的显隐开关与窗口行为见 [群聊页签](群聊页签.md)。


## 角色依赖图

消息流上方还有一张**依赖图**（随「群聊」tab 一起出现，见
[群聊页签](群聊页签.md)）：把消息按方向聚合成 `A → B` 这样的箭头，
每行右侧标注这个方向的 **@ 次数**；**点一下箭头就展开多行时间流**（每行一个时刻，精确到秒，
带该次消息的正文摘要与送达状态）。分组细节见下面的「角色依赖图：一对 mapping 一行」。


### 角色依赖图：一对 mapping 一行（§5.51，用户 m15312）

R7.1–R7.4 的第一版是**一个方向一行**：`lead → accept-probe @2` 与 `accept-probe → lead @2` 各占一行，
同一对人被画了两次。用户发来群聊 tab 的截图说「感觉这样两行不太方便看，是不是可以合并成一行，
一对 mapping 就是一行，如果还有一个开发者，就是两行」——所以行数应该跟着**人**走，不是跟着**方向**走。

- **分组键改无序**（`lib/client.js` 的 `foldPairs`）：`const key = fromId < toId ? \`${fromId}~${toId}\` : \`${toId}~${fromId}\``，
  命中同一对人时按方向计两个数——`pair.out`（left → right）与 `pair.back`（right → left），
  `pair.rows` 仍然是两个方向混在一起的 seq 序（时间线合并着读）。
- **一行 = 名字 / 箭头 / 名字 / 计数**：两个方向都有就是 `lead ⇄ accept-probe` + `@2 ⇄ @2`（悬停给出
  「`lead → accept-probe 2 条；accept-probe → lead 2 条`」）；只有一个方向时退回老读法 `A → B @n`，
  且**发起方在左**（`const flip = !both && pair.out === 0`）。
- **合并后的时间线要标方向**：两个方向都在的行，每条前面补一个 `→` / `←`（相对左侧那个人，悬停给全名），
  否则看不出这一条是谁 @ 谁。单方向的行不加这个箭头（全是同一个方向，加了是噪声）。
- 三个参与者、四个方向 ⇒ **两行**（`accept-probe~lead`、`dev-2~lead`），正是用户说的「如果还有一个开发者，
  就是两行」。
- 测试：`foldPairs` 里没有闭包依赖（只用 `Map` / `String`），所以它在 `lib/client.js` 里被
  `//--- foldPairs:start/end ---` 标记围起来，`tests/plugin/ui-and-log.test.mjs` 的 §5.51 直接把这段源码抠出来在
  `node:vm` 里**真跑一遍**（两个方向折成一行、键无序、镜像输入同键、三个参与者两行、单方向仍旧），
  另加一条源码断言盯着行渲染（`⇄` / 两个计数 / 时间线方向标 / flip 顺序）。
- 真机复验（重启后的 web 会话，刷新页面即生效——客户端侧不需要重启 dsh）：群聊 tab 里从两行变成
  一行 `lead ⇄ accept-probe @2 ⇄ @2`，展开后四条 PING/PONG 带 `→ → ← ←` 方向标依次排列。
