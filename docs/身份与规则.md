# 身份与规则

## 身份与规则（AGENTS.md 路径）

角色的「身份」不是单独一维：`persona`（系统提示里那句身份/工作目录说明）与 `agent-instructions`
（规则文件）在界面里**同一类**，标题是「**身份与规则**」。每个角色有**自己的一份** `AGENTS.md`：
新建角色时**固定**从用户全局 `$DSH_HOME/AGENTS.md`（Windows 下即 `%USERPROFILE%\.dsh\AGENTS.md`）复制一份，
放在**角色自己的目录**里（而那个目录同时就是角色的工作目录，
所以 dsh 一定读得到它）。面板上第一行显示的就是这份文件的完整路径，以及它是从哪复制来的。

> **为什么不复制项目里的 `AGENTS.md`**（§5.42，用户 m10519）：成员进入某个项目时，
> dsh **会自动**读到那个项目的 `AGENTS.md`（会话工作目录向上发现的候选链），
> 复制进角色目录只会把项目规则冻成一份会过期的快照。所以角色的文件 = **你的**标准规则，
> 项目规则继续走 dsh 自己的发现链（角色目录优先、项目规则补充，见下面
> 「角色的 `AGENTS.md` 是怎么被读到的」）。

面板剩下的三个输入框写的是 `agent-instructions` 行的三个发现键——如果你想改变"找哪些文件名"，
这是角色能影响的**唯一**杠杆（插件按文件名从会话工作目录向上找）：

| 字段 | config 键 | 该行自己的默认值 |
| --- | --- | --- |
| 指令文件名 | `instructionFileCandidates` | `AGENTS.md, CLAUDE.md` |
| 本地指令文件名 | `localInstructionFileCandidates` | `AGENTS.local.md, CLAUDE.local.md` |
| 项目根标记 | `projectRootMarkers` | `.git` |

字段留空 = **继承模板**。快照里这一行只有 `{"maxBytes":65536}`（另外三个键是 schema 默认值，
不在快照里），所以默认值是以「**插件默认：…**」的**提示文本**出现的——只作提示，绝不会被自动写进去。

这个面板**只管"去哪几个文件名里找"**；「要不要加载 AGENTS.md」是另一件事，由能力行表
「身份与规则」里 `agent-instructions` 那一行的开关决定（关掉 = 这个角色完全不读任何
AGENTS.md / CLAUDE.md）。两个控件各自回答一个问题，所以没有合并成一个。

面板右上角的「**还原默认**」= 重新从用户全局 `$DSH_HOME/AGENTS.md` 复制一份覆盖这个角色的文件（`item: 'agents-md'`），
同时清掉这一行被改过的键。

角色详情里的顺序按用户要求（m05741）：**要先填的在上**（角色工作目录 → 身份与规则），
**勾选类的在下**（能力行表，MCP 开关收在它里面）。最上面那个「角色工作目录」面板是**只读**的
（用户 m06762：「只是显示一个路径，不改路径」）。

「能力行」那一段从 2026-09-28（用户 m08302）起是这个顺序：**标题 → 还原默认 → 搜索框行 →
MCP 开关 → 表头 → 各分组**。MCP 原来是一块独立面板，现在由 `GroupedTable` 当 `children` 渲染。
层级上它是**和「技能」「插件」那些分组并列的一层**，不是缩进在下面的子层级（用户 m08489
「mcp和技能等是同一层级，不是单独子层级」）：标题横向 padding 与分组行对齐，server 行沿用同一套行样式。
MCP 标题行用的是和分组标题行**完全同一套样式**（同一块灰底、同一个两列网格 `1fr 90px`），
所以它右边那个「全部 server 一起开 / 关」复选框和各分组的「整类开关」落在同一列上
（用户 m09219「为啥mcp这一行不是和下面的一样是灰色？」+ m09281「mcp没有全开/关的按钮」）。
同一条要求还带来「勾一下全表变灰」的修复：「进行中」从**面板级**降到**控件级**
（`row:<行 id>` / `mcp:<server>` / `context:tool-subagent`），点下去先乐观画出目标状态、
回包后再以 `/state` 为准；只有结构性动作（新建 / 删除 / 还原 / 改模式 / 团队开关）仍用全局锁。

表头（用户 m08545 之后）只剩右列的 **`启用`** 这个列标签：原来左半边那句「来自部署的 <模式> 模板」
紧贴在 MCP 块正下方（只隔 6px），读起来像 MCP 的说明，而且和「能力行」标题的 ⓘ 说的是同一件事。
**MCP 开关与各能力行分组默认全部折叠**（同一条 m08545：「默认都折叠起来」）——`GroupedTable` 记的是
**被展开**的类（`expanded` 集合从空开始，空集合就是全折叠），`McpPanel` 的 `open` 默认 `false`；
想看哪一类点它的 `▸` 展开。

发送时为空字段同时带两种拼法：`config[key] = null`（宿主把它读作「从生效配置里删掉这个键」）
以及 `clearConfig: [...]`（把键从**已存的覆盖**里删掉，让这行重新算「跟随模板」）。
后者是较新的一版宿主逻辑，**旧的宿主会静默忽略它**——届时功能仍正确，只是这行会一直显示「已被这个角色改过」。
