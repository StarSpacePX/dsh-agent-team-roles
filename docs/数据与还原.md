# 数据与还原

## 目录

角色数据放在 `<dsh home>/agent-team-roles/`，默认是 `~/.dsh/agent-team-roles/`。插件配置 `dir` 可以改到别处。

```
agent-team-roles/
├── roles.json          版本号与全局设置
├── notes.json          面板顶部的说明文字（可选）
└── <角色 id>/
    ├── role.json       这个角色的配置
    └── AGENTS.md       这个角色自己的规则文件
```

一个角色一个目录。改哪个角色只动哪个目录。

## role.json 字段

| 字段 | 说明 |
| --- | --- |
| `id` | 角色 id，小写字母数字与连字符，首个字符不能是连字符；不能是 `standard` / `cordis` / `minimal` / `ptc` |
| `name` | 面板上显示的中文名，不超过 80 字 |
| `description` | 一句话描述，不超过 400 字 |
| `order` | 列表里的排序，默认 10 |
| `mode` | 基于哪个模式：标准、cordis、极简、ptc，缺省按标准 |
| `overrides` | 按模板行改的开关与配置 |
| `capabilities` | 隐藏的 MCP 与工具名单 |
| `skills` | `mode` 是 `inherit` 或 `pick`，`ids` 是勾选的技能名 |
| `agentsMd` | `AGENTS.md` 从哪来、什么时候复制的 |
| `color` | 角色颜色 |
| `createdAt` / `updatedAt` | 创建与最后修改时间，自动盖 |

`overrides` 按模板行 id 记开关；`capabilities` 只装 MCP 和工具的隐藏名单。两张表不混用。

## AGENTS.md

新建角色时，把用户全局的 `AGENTS.md`（`<dsh home>/AGENTS.md`）复制一份进去。项目里的不复制，dsh 自己会从工作目录往上找。用户全局那份不存在或为空时，写一个占位文件。

## 从旧版迁移

旧版把所有角色内联写在 `roles.json` 的 `roles` 数组里。首次加载时每个角色写进自己的目录、补一份 `AGENTS.md`，全部写成功后才重写 `roles.json`。
## 坏了会怎样

| 情况 | 表现 |
| --- | --- |
| 某个 `role.json` 读不出来 | 只有这一个角色显示「无效」，其它照读 |
| `role.json` 的 id 与目录名不一致 | 同上，标「无效」 |
| 角色没有颜色 | 读盘时补一个写回，不用手动改 |

改角色 id 时，目录名、`role.json` 的 id、注册名三样一起换，`AGENTS.md` 跟目录走。空 id、重名、内置名、非法字符四种情况在动目录之前就挡下。

## 四种还原

| 层级 | 做什么 | 保留什么 |
| --- | --- | --- |
| 新建角色 | 建目录、复制 `AGENTS.md`、写 `role.json`，默认标准模式 | — |
| 全部还原 | 模式回标准、行开关清空、MCP 与工具名单回默认、技能回继承 | 名字、描述、排序、`AGENTS.md` 文件 |
| 逐项还原 | 见下表 | 其它项 |
| 删除角色 | 删掉整个角色目录 | 什么都不留 |

逐项还原的三个目标：

1. `agents-md`：重新从用户全局复制一份 `AGENTS.md`，并清掉规则行上的覆盖。
2. `rows`：清空行开关，以及 MCP 与工具的隐藏名单。
3. `skills`：技能回到继承，勾过的名字保留，方便再勾回来。

## 备份与卸载

备份就是拷 `agent-team-roles/` 整个目录，恢复就是拷回去再点面板「刷新」。卸载插件不删这个目录，重装回来角色还在。

## 生效

改完存盘立即生效，面板显示「已存盘 · 下次用到该角色时生效」。不用重启 dsh。
