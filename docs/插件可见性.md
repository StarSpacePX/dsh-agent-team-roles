# 插件可见性

## 插件可见性：按角色遮蔽全局工具（§5.55，用户 m18131 / m18179）

用户在截图里提了两件事：「角色可见性禁用就行，你加一下，在 mcp 和技能中间」+「另外搜索框以及统计
好像对技能 / mcp 没有生效」；名字随后定为**「插件」**。落地的东西分两半。

**宿主半**（`lib/deployment.js` / `lib/roles.js` / `lib/host/gate.js` / `lib/host/state.js`）：

- 存储是**精确工具名**：`capabilities.toolGate.deny = ['ego_click', …]`（`defaultCapabilities()` /
  `normalizeCapabilities()` 与 `mcp.deny` 并列，丢 `run_code`）。不给按插件分组：`tools.schemas()`
  的投影只给 `{name, description, parameters}`，**没有 owner**，按插件分簇根本查不出来。
- 组合出一行 `{ id: 'agent-team-tool-gate', name: 'dsh-agent-team-roles', config: { toolGate: { deny } } }`
  （`buildToolGateRow()`，空名单返回 `null`；与 MCP 网关行并列，仍是 `roles.js` 追加、`composeRows`
  一行不改）。清单为空 ⇒ **没有这一行**，没碰过面板的角色组合结果与从前逐字节相同。
- 挂载时（`applyToolGate`）先 `tools.schemas()` 取这个 agent scope 的 live 清单、与存下来的名字
  **求交集**，空则整个跳过 —— 名字在注册前就写进 JSON 也不会让挂载抛错（注册表对未知名直接抛）。
- `/state` 多一段 `toolGate: { error, tools: [{ name, description }] }`：从**根 scope** 读一次
  `schemas()`（内存里的，不读盘），去掉 `run_code`（注册表禁止 restrict）与 `mcp__*`（MCP 面板按
  server 整片管），描述截 160 字。读不到就说 `tools 服务不可用，读不到工具清单`，**不是**空面板。
- 写路径照旧走 `set-switches`：新增 `body.tools`（`{名字: 布尔}`），与 `rows` / `mcp` 一条请求
  （一次手势 = 一个请求 = 一次重建）。名字要过 `TOOL_NAME_PATTERN`，且**当清单可读时**拒绝部署里
  没有的名字（`这个部署里没有工具：…`）；清单读不到时**放行** —— 缺 `tools` 服务不该让面板变只读。

**客户端半**（`lib/client.js`）：

- 三个可折叠块现在**共用一份条目清单**：`mcpEntries()` / `skillEntries()` / `toolEntries()` 各返回
  `{ key, item, text, off, changed }`，`filterEntries()` 是唯一那条过滤规则。面板渲染的就是这份清单，
  「共 N 行 · 显示 M · 已关 K · 被覆盖 J」数的也是它，所以数字与列表不可能对不上（这就是那句
  「搜索框以及统计好像对技能 / mcp 没有生效」的修法）。统计从 `共 32 行` 变成 `共 121 行`。
- 过滤框覆盖三块（placeholder 改成「过滤：包名 / 行 id / 行名 / MCP server / 技能 / 插件」），
  「只看被角色改过的行」也一样：勾上 + 过滤 `ego` 只剩被改过的那一行（3099 真机）。
- 新面板 `PluginsPanel` 位置就是用户指定的那一格：**MCP → 插件 → 技能**；标题
  `插件（部署里有 67 个可禁用的工具）`，默认折叠，右上角是全选（半选 = 一部分），
  逐行一个开关 + 悬停显示名字与描述，空结果说「没有匹配的工具（清掉过滤框，或取消「只看被角色改过的行」）」。
- 它是 React，`React.createElement` 不接受函数 child，所以三块是走 `panels({ needle, onlyChanged })`
  渲染道具拿到的，不是把 `children` 当函数调用。

**一条必须知道的边界**：它列的是**根层（全局）注册**的工具 —— 3099 真机上 67 个，全是
`ego_*`（dsh-ego-browser）、`mcp_connector_*` / `read_mcp_resource`（dsh-mcp-connector）以及
`compress` / `absorb` / `GitForge` 这类宿主工具。**预设行在 agent scope 里挂的东西不在里面**
（`pwsh` / `read` / `write` / `edit`、以及 Agent Teams 那几个工具如 `spawn_teammate` / `list_agents`），
那些属于上面「工具 (19)」分组的职权：关那一行等于**不挂载**，这里关掉的只是**可见性**。
两条路各管一层，面板里的 ⓘ 就是这么解释的（`notes.js` 的 `toolGateVsRows` / `toolGateScope`）。

- **测试**：`tests/plugin/panels.test.mjs` 与 `tests/plugin/ui-and-log.test.mjs` 的 `§5.55` 区间 5 条（根层清单过滤 `run_code` 与 `mcp__*` 并截断描述、
  一个工具开关物化出第二行网关行、拒绝部署里没有的名字 / 非法名 / 非布尔、清单读不到时仍可写）+ 2 条
  客户端源码断言（面板位置与顺序、三块条目助手与统计口径）；`tests/deployment.test.mjs` 覆盖
  `normalizeCapabilities` 两段名单与 `buildToolGateRow`（空 / 只有 `run_code` 返回 `null`）。
- **真机验收（3099，第二实例）**：`/state.toolGate` = 67 个工具、`run_code` 不在、`mcp__*` 不在；
  取消勾选 `ego_click` ⇒ `team-rfozlm` 的 `capabilities.toolGate.deny = ['ego_click']`、后台重建后
  `deferred` 清空；统计 `已关 21 → 22`、`被覆盖 22 → 23`；勾回来后名单回空、角色文件恢复原状。
  截图：`Test\_gui-5.55-plugins.png`。**宿主半改动仍需重启 dsh 才生效**。

## 插件的整组勾选与启动预热（§5.55 补，用户 m18765）

两个问题，一句原文：「1.这个读取要好几秒是什么意思？2.插件里面的mcp_connect/ego等，为啥平铺出来的？
我一个个选得多麻烦？一个大类的要能整体勾选」。

**「正在读取角色…」是等本进程第一次 `/state`**（`lib/client.js` 里 `state === null` 只画这句话）。
这一次要跨 `@Remote` 读一遍部署组合清单（`pluginManager.listBundles()`，宿主侧同步读 profile manifest
+ 每个组合包的 `package.json`），实测 3080 第一次 **516 ms**、3099 冷进程 **3965 ms**，之后 80–600 ms。
所以启动 IIFE 里 `sync()` 之后排一个 `TEAM_WARMUP_DELAY_MS = 2_000` 的 `warmTeamCache()`，到点在
**请求路径之外**先读掉（`unref()`，卸插件时 `invalidateTeam()` 清掉定时器）。诚实说：它只覆盖
「启动过一会儿再打开设置」；预热排在 +2 s 而那次冷读本身要 3.7–6 s，**刚启动的头几秒**打开仍会等
（实测 5960 ms）。彻底消除要改宿主别在同步路径上读盘，不在这条范围内。

**整组勾选**：清单里没有 owner 字段（`tools.schemas()` 只投影 `{name, description, parameters}`），
能用的信号只有名字前缀 ⇒ `TOOL_GROUP_MIN = 3` 个同前缀的成一组（这份部署：`ego` 33、`mcp` 23、
`acp` 3，其余 8 个平铺），组头一个勾选框整组开关（半选 = 组里关了一部分），默认收起，搜索或
「只看被角色改过的行」时自动摊开。整组写下去的还是逐个精确工具名、仍是一条 `set-switches` 一次重建。

**行表格的对齐（用户 m18888）**：重启后用户看着「工具 (19)」那一类问「这些为啥没有和左边对齐？」——
凡是某个分组的成员（`delegation/tool-subagent…`、`compaction/tool-result-pruner`）原先都套
`styles.child`（`paddingLeft: 22`），同类的兄弟行只有 6px。可那张表是**按 `row.path` 平铺、按类别
分组**的：这些行的父行（分组本身）在另一类「分组」里，压根看不到，所以这点缩进不表达任何可见层级，
只显得错位。整条去掉（`lib/client.js`），层级仍由行名自己说（完整 `row.path`，`delegation/…`）。
真机复测：19 行**全部** `x = 450`、`paddingLeft: 6px`（改前分组行 `x = 466`）。

**一条实测出来的好消息**：客户端半（`lib/client.js`）**不用重启 dsh** —— dsh 把各插件的 client 一起
打进 `/plugins/??…&rev=<hash>`，页面刷新就会按新内容重算 rev 并重新打包（实测：刷新后 bundle 里出现
新注释、旧样式没了，rev 从 `81bab32cc30d` 变成 `4979fbc456cb`）。宿主半（`lib/index.js`、`lib/host/` 等）才需要重启。
