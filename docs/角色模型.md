# 角色

角色就是一枚**独立可选的 agent preset**：插件启动时注册进 dsh，出现在 preset 选择器里，
可以和内置的 `standard` 一样被选中。

- **只引用，不新增**：角色的能力行来自部署当前的预设，角色只在其上做开关
  （外加 AGENTS.md 面板的三个发现键）。
- **不碰现有文件**：只写自己的数据目录，不改 dsh 包、不改内置预设、不改 `settings.yaml`。
- 页签栏「角色」页配置角色；团队消息看官方自带的「群聊」页签。

## 数据

一个角色一个目录：`<id>/role.json` + `<id>/AGENTS.md`，索引在 `roles.json`。
默认放在 `<dsh home>/agent-team-roles`，可用 `dir` 配置项改。

## 新建角色

- 填名字，可选填**角色 ID**（= 成员名）。ID 只能用小写字母、数字、短横线；留空就按名字自动生成。
- 敲 ID 时就回显「角色 ID：team-qa-1 · 成员名：qa-1」，非法字符时保存按钮禁用。
- 成员名 = ID 去掉 `team-` 前缀，`spawn_teammate` 用的就是这个名字。

## 改角色 ID

在详情面板「名字」下面一行。保存时**目录、`role.json`、preset id 一起换**，
角色自己的 `AGENTS.md` 跟着目录走；覆盖行按行 id 存，不受影响。

ID 被占用、不合规、或撞上内置 preset 名，保存前就拦下，目录不会搬一半。

已经建好的成员**不会跟着改名**——成员名用过就不能改，改名只影响以后新建的成员。

## 能力行表

| 操作 | 说明 |
| --- | --- |
| 过滤框 | 按包名 / 行 id / 行名做子串过滤 |
| 只看被角色改过的行 | 只剩带角色覆盖的行 |
| 整类开关 | 分类标题行的三态复选框 = 全开 / 全关，半选表示开了一部分；只作用于当前可见的行 |
| 折叠 | 点分类标题收起 / 展开，默认全部折叠 |

- 点一下立刻画出目标状态，120 ms 内的多次点击合并成一次提交；失败会收回乐观状态并重读。
- 没有逐行 config 编辑器；行名悬停可看该行的 config。
- 「还原默认」清掉这一行的覆盖与 MCP 勾选；角色级「全部还原」保留名字与 `AGENTS.md`。

## 模型

每个角色可以单独指定 provider、模型、推理强度；成员绑到这个角色后，被创建时就用这套。

| 状态 | 行为 |
| --- | --- |
| 跟随部署（默认） | 三格都空，成员用部署默认模型 |
| 指定 | 成员的第一轮请求就按角色这套走 |

- provider 与模型要么都给、要么都空；只填一半保存被拒。
- 只作用于成员；主会话（lead）的模型由用户开会话时选的那枚 preset 决定，与角色无关。
- 两个角色用同一个模式当模板也各带各的模型。
- 不改部署默认：设置只写进成员自己那条会话，重开会话回到默认。
- 候选清单来自部署已装的模型适配器；读不到时可手填 id。
- 落点：成员创建时往**它自己的会话**写一条 `model/selection`（agent 作用域），成员第一轮请求就用它；
  角色预设里不加任何模型行。

接口：`POST /command` `{action:'set-model', id, provider, model, reasoningEffort}`。

## 生效

宿主侧改动（注册、绑定、写角色文件）**要重启 dsh**；界面部分刷新页面即可。
面板会如实回报「已生效」或「已保存，重启 dsh 后生效」。
