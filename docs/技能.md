# 技能

## 技能：每个角色自己选用（§5.47）

用户 m11777：「技能也要能单独配置，配置底层就直接改成员自己的 preset 吧…是不是要单独领出来复制
preset 文件，不能动原本的」。**不用复制任何文件——preset 文件与技能目录都不动**，评估见
`Docs\评估-技能按角色配置.md`。原因是两件已经成立的事：

- 角色本来就是「模式快照的一份**内存派生副本**」（`lib/roles.js` 的 `buildDefinition`），
  磁盘上的 `presets\*.patch.yml` 从头到尾只被读过；
- 模式里已有的 `skill-filesystem` 行**本来就有**按目录选技能的两个键，而 `discoverRoot` 接受
  「root 条目本身就是一个技能目录」（`…\@deepseek-ai\dsh-skill-filesystem\lib\index.js:56-89`、`:150-188`）。

所以「这个角色只用这几样技能」= 覆盖**已存在**的那一行的 config：

```json
{ "includeDefaultRoots": false, "customSkillDirs": ["<技能目录>", "…"] }
```

`includeDefaultRoots:false` 关掉项目/用户那几个默认根，`customSkillDirs` 就是被勾中的技能的目录
（目录型技能用目录本身，单文件技能用它的父目录）。零磁盘产物、零复制、零链接。

- **两种模式**：`inherit`（默认，= 这个角色跟以前一模一样）与 `pick`（只挂勾中的）。面板上那个
  复选框切换它；**在列表里勾一个技能会自动切到 `pick`**（「勾选就是选用」，m11895 / m11916），
  不需要先开开关再回来勾。
- **勾选名单两种模式都留着**：切回 `inherit` 不丢选择，再切回 `pick` 就是原样。
- **勾选即存**：每点一下就发一次 `set-skills`（一个手势一个请求），回包自带新 `/state`；
  不是只在浏览器里攒着。
- **客户端半的渲染在重启前就验过了**：宿主半要重启才有 `skills` 段，但渲染代码早就在页面里 ——
  真机页面上给 `window.fetch` 打一层拦截、喂一份形状正确的合成 `/state`（18 个技能 + `role.skills`），
  就能把 `技能` 一行完整展开：勾一个 → 请求确实是 `{ action:'set-skills', id, mode:'pick', ids:[…] }`、
  标题变「只挂勾选的 1 个」；取消勾选 → `ids:[]`（「取消就是不加载」）。
  写操作也在拦截层里回假 200，**没动真数据**：跑完 `roles.json` / `role.json` 的 SHA256 与跑之前一致。
  证据 `Test\gui-skills-panel-fake-state.png`；手法见 `KeyNotes\假后端验渲染.md`。
- **名单是「意图」，挂载是「事实」**：磁盘上没了的技能仍留在名单里（`role.json` 里还有），
  `/state` 把它列进这个角色的 `skills.missing`，面板红字标「这个部署里已经没了，装回来才会挂载」，
  组合时**不挂**——不会因为卸载一个技能就炸掉整个预设。
- **只接受这个部署真的有的技能名**：`set-skills` 用一个不认识的名字回 400
  （`这个部署里没有技能：xxx`），不会存进一份看起来没问题的空选择。
- **极简模式**没有 `skill-filesystem`，也没有 `tool-skill`（消费面）。勾技能会**成对**补上这两行
  （`skillRowsFor`）；`/state` 的 `skills.hasFilesystemRow` / `hasToolRow` 让面板把这件事说出来。
- 技能的**清单**由宿主半自己扫（`lib/skills.js` 的 `scanSkills`）：项目 `.dsh/skills`、
  项目 `.agents/skills`、`~/.dsh/skills`、`~/.agents/skills`，按同一优先级去重，和加载器一致；
  一个根本不存在不算错，读不了才报错。找不到 `SKILL.md`、或 frontmatter 没有 `name` 的条目
  **不列出来**（加载器也会跳过它们，列了就是一个勾了不生效的复选框）。
- ⚠️ **全局层筛不掉**：`dsh-skill` 的 `collectFresh` 是 `[global, ...角色链]` 合并、近层同名覆盖，
  没有 deny 表（`…\@deepseek-ai\dsh-skill\lib\index.js:298-311`、`:95-107`）。某个部署级 provider
  注册的技能对所有角色恒可见，这里只能**同名遮蔽**，不能删除。面板的 ⓘ 里如实写了这一条。
  实测（2026-09-28，`Test\probe-skills-real.mjs`）：本部署的 `@michengai/dsh-skills-manager`
  **只在需要强制策略时才注册全局 provider**（`lib\core.js:2252-2258` 的 `if (!needsOverlay) continue`），
  而 `~/.dsh/skills` 是它眼里**可变**的根、默认 policies 为空 ⇒ `~/.dsh/skills` 那 18 个技能**当前不在全局层**，
  这一层的筛选是真正独占的。只有**只读来源根**（`~/.agents/skills`、`~/.claude/skills`、`~/.codex/skills` …）
  里的技能会被它**永远**覆盖注册 ⇒ 那些对所有角色恒可见；以后若在技能管理器里给某技能设了全局开/关，
  那一条也会绕开这个面板。
- ⚠️ 这一项在**宿主半**（`lib/skills.js` + `lib/store.js` + `lib/roles.js` + `lib/host/state.js`、`lib/host/lifecycle.js`、`lib/host/commands-role.js`），
  改动**要重启 dsh 才生效**；面板本身在客户端半，刷新页面即可。宿主半没重启时，`/state` 里没有
  `skills` 段，面板显示「宿主半还没重启」而不是假装列不出来是正常的。

HTTP 上的形状：

```jsonc
// 请求
{ "action": "set-skills", "id": "team-architect", "mode": "pick", "ids": ["push", "pptx"] }
// 回包（多一个 skills，state 与其它 action 同形）
{ "action": "set-skills", "id": "team-architect", "skills": { "mode": "pick", "ids": ["push", "pptx"] }, "result": {…}, "state": {…} }
```

`/state` 里多两处：顶层 `skills` = `{ roots, available, error, row }`（`available` 是清单，
`row` 是那两个行 id / 包名），每个角色多一个 `skills` = `{ mode, ids, dirs, missing,
hasFilesystemRow, hasToolRow }`。`reset-item` 多了 `item: "skills"`（只把模式拉回 `inherit`、
**保留**已勾名单），`reset-role` 则连名单一起清空。存储格式版本 `roles.json` 的 `version` 从 2 升到 3。
