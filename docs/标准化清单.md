## 安装路径（已验证的机制）

- `dsh plugin --profile <name> add <pkgspec>` 把参数原样转发给 profile 目录里的 pnpm，
  并在 pnpm 成功后**自动 reconcile `dsh.profile.bundles`**（新装的 bundle 会补进行里）。
  源码：`@deepseek-ai/dsh-plugin-manager/lib/types/operations.js:95-122`「Reconcile package removals and newly installed bundles」。
- 所以标准安装对用户就是一条命令 + 重启 dsh，**不需要手工编辑 profile 的 package.json**。
- 当前插件的 `README.md:59-76` 教用户手工改两处（dependencies + bundles）+ `link:` 本机绝对路径，
  这是本机自用流程，开源必须换掉。

## 改造方案

### 1. package.json 重写（P0）

- 去掉 `private`；补全 `license` / `repository` / `bugs` / `homepage` / `author` / `keywords` / `publishConfig`
- `files` 白名单：`lib` `src` `tools` `templates` `cordis.patch.yml` `README.md` `README.zh-CN.md` `LICENSE` `CHANGELOG.md` `docs`
  （`tests` 不发布，但**进 git**——按本机规范测试脚本要保留）
- 补 `engines.dsh`，与 `package.json` 里 `engines.node` 并列
- 补 `peerDependencies`：与 dsh 的版本区间对齐（`>=0.2.0-rc.1 <0.3.0-0`）

### 2. 新增仓库根文件（P0）

- `LICENSE` —— 类型待定，见下方「待拍板」
- `.gitignore` —— `node_modules/`、`logs/`、`*.log`、`tmp/`、`.DS_Store`
- `CHANGELOG.md` —— 从 0.1.0 起，Keep a Changelog 格式
- `CONTRIBUTING.md`（可选）—— 开发命令三条

### 3. README 重写（P0）

新结构（中英双语，`README.md` 英文 / `README.zh-CN.md` 中文，与参考插件一致）：

1. 一句话简介 + 一张截图
2. **Install** —— `dsh plugin --profile web add <pkg>` + 重启 dsh（一条命令）
3. **Quick start** —— 打开「角色」页签 → 启用团队 → 建角色 → 绑成员
4. **Configuration** —— `dir` / `prefix` / `bindMembers` / `home` 四个键的表格（从 `docs/配置项.md` 搬）
5. **What it does** —— 能力表
6. **Data & Uninstall** —— 数据在 `<DSH_HOME>/agent-team-roles/`，卸载后手动删
7. **Docs** —— 指向本仓 `docs/` 的索引（删掉 `../../Docs/teams` 外链）
8. **Development** —— `npm test` / `npm run build:client`

### 4. 安装脚本（P1，可选）

若想让「不装市场的人」也一步到位，加 `tools/install.mjs`：
读 `DSH_HOME` → 调 `dsh plugin --profile <name> add <pkg>` → 校验 bundles 行 → 打印重启提示。
与「安装路径标准化」重复度高，先不做，看是否需要。

### 5. 日志标准化（P1）

- 保持 `ctx.logger('agent-team-roles')`（这是 dsh 正规通道，不自己造文件日志）
- 新增 `docs/日志.md`：说明名字前缀、落点（dsh 日志）、排查命令
- 不新增临时调试后门

## 待拍板（3 件）

1. **许可证**：`MIT`（最宽松、社区最认）还是 `Apache-2.0`（参考插件用它，带专利授权）？
2. **npm 包名**：保持 `dsh-agent-team-roles`（市场里同类多为无 scope），还是 `@starspacepx/dsh-agent-team-roles`？
   —— 无 scope 更短、别人 `dsh plugin add` 好打；带 scope 不会撞名。
3. **发布范围**：只发 GitHub + 市场按 git 地址装，还是同时发 npm？
   —— npm 发布后用户装起来最快、能锁版本；git 装则零发布成本但要 pnpm 允许构建。
