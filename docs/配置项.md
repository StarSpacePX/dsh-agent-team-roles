# 配置项

## 配置项

插件配置（本仓把它写在 `cordis.patch.yml` 的 `config:` 段里）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `dir` | `null` | 数据目录；留空则用 `<dsh home>/agent-team-roles` |
| `prefix` | `"team-"` | 自动生成 preset id 用的前缀 |
| `bindMembers` | `false` | **强制打开**成员绑定（见「成员绑定」；**改了要重启 dsh**）。关着也不代表绑定关闭，见下 |
| `home` | `null` | dsh home（读 MCP 连接器存储用）；留空走 `DSH_HOME` 或 `~/.dsh`。主要为测试留的注入点 |

没有 `template` 键：角色的模板就是它 `mode` 指定的那份预设，运行时从 Loader 的声明里**现场读**
（§5.62，用户 m13273「只引用，不独立」），插件不再打包任何模式的抄本，所以配置里给不出第二个模板。

成员绑定有两个来源，**取或**：

1. **插件配置** `bindMembers: true` —— 部署决定，改它要重启 dsh；界面上会显示「已被插件配置的 bindMembers 强制打开」，且开关置灰。
2. **界面开关**（`settings.bindMembers`，写在角色文件里）—— 随开随关，不用重启。

`GET /state` 会回 `bindMembers`（最终是否生效）与 `bindMembersSource`（`config` / `store` / `off`）。
界面在 `bindMembersSource` 缺失时（= 宿主半还是旧代码）会把开关置灰并提示「重启 dsh 后这个开关才可用」，而不是假装能点。
