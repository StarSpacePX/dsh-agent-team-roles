# MCP 开关

## MCP 开关（对「只引用不新增」的**唯一**一条定向例外）

六类开关里，工具 / 技能 / 分组 / AGENTS.md 都落在角色 preset **已有的行**上；MCP 在 preset 树里
**根本没有行**，所以这一类走的是**经用户明确授权的定向例外**（原话：「mcp加开关 ，loop加路径选择以及
可以复制标准模式」）。除这一条以外，R3「只引用不新增」照旧。

> **loop 那一类已经被整体拆除**（§5.30，2026-09-28）：见
> [边界与扩展点：没有 loop 行](边界与扩展点.md#没有-loop-行)。角色的 `AGENTS.md`
> 也不是新增行，而是给已有的 `agent-instructions` 行加一个 `config.dshHome`（见
> [数据与还原](数据与还原.md#数据放在哪)）。

### MCP：每个 server 一行开关

角色详情里的「**MCP 开关**」在界面上摆**在搜索框正下方、能力行分组同一层**（2026-09-28 起，用户 m08302
「mcp放到搜索框下面去」；用户 m08489 随后点明「mcp和技能等是同一层级，不是单独子层级」），按**每个 MCP server 一行**列出，各自开 / 关。
它**默认是折叠的**（用户 m08545「默认都折叠起来」），点标题左边的 `▸` 展开。数据源是**连接器自己的磁盘
文件**（`~/.dsh/storages/mcp_connector.json` 的 `tables.connections`），插件**只读**它——你在 MCP
连接器里加 / 关 server，面板下次读 `/state` 就能看见。

**勾选就是启用，没有第二层「总开关」**（用户 m08267：「mcp上面勾选了就启用」）：面板上那一列勾选框
就是 MCP 这一维度的**全部**开关粒度，一个 server 一个。同理 loop 那一维度也不需要开关——它就是角色详情
最上面的**模式下拉框**（必选一个，默认 `standard`，不选即默认，见「模式（从部署现有的预设里选一个）」）。

**标题行那个复选框 = 全开 / 全关**（用户 m09281 1./2.，2026-09-28）：MCP 标题行和下面的分组标题行
长得一模一样，右边第 2 列是一个三态复选框——全部 server 一起开 / 关，半选表示只开了一部分；
各分组行右边原先那两个「全开 / 全关」中文按钮已经删掉（和复选框重复）。

关掉一个 server 不是去卸载它（那会打断别的角色），而是给角色挂一个**隐藏层**：取消勾选会在该角色的
preset 里加一条 `agent-team-mcp-gate` 行 —— 那是**本插件自己的第二个挂载点**，它在这个 agent 自己的
作用域里调用 `tools.restrict({ deny: [...] })`，把 `mcp__<名字>__*` 从这个 agent **能继承到的层**里摘掉。
这条行不提供任何工具，只隐藏部署里已经存在的工具。

deny 名单在**挂载时**现算，不在保存时写死（连接器可能后开、后关、改名）：实现是拿 `tools.schemas()`
与 `mcp__<serverName>__` 前缀求交集；交集为空就记一条 info 日志，**不报错、不阻断挂载**。

`capabilities` 与 `overrides` 在角色的 `role.json` 里**分开存**：`overrides` 的键是快照里的**行 id**，
若把 `mcpGate` 混进同一张表，一个打错的行 id 就没法和一个合法的能力键区分了。
