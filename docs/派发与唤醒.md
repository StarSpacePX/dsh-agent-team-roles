# 派发与唤醒

派发靠两条路：用户在输入框打 `@成员名`，或者插件的任务板自动唤醒。

## @成员 派发

1. 在 Lead 会话的输入框打 `@`。
2. 候选里列出团队成员，按前缀过滤。只列非 Lead、且没有失败的成员。
3. 选一个，`@名字` 后面敲空格，这一句话就认给这个成员了。
4. 继续写正文，回车发送。

消息直接投给那个成员。这句草稿不进模型，也不留在 Lead 的会话里。

`@` 后面不是成员时照旧走 dsh 原来的 `@文件`、`@会话`。

在成员自己的会话里打 `@` 也有效，消息一样经 Lead 投递。

成员消息在官方「群聊」页签里看，不能在那里发；发消息走 `@成员`。

## 派发失败时

| 情况 | 提示 |
| --- | --- |
| 正文是空的 | `正文是空的，没有发送。` |
| 缺会话 | `缺少 sessionId` |
| 缺成员名 | `缺少成员名` |
| 这个部署没有任务板运行时 | `这个部署里没有 Agent Teams 运行时，没法把消息交给成员` |
| 会话不在线 | `这个会话不在线，没法把消息交给成员` |
| 运行时拒绝 | `没能把消息交给「名字」：<原文>` |

请求 15 秒没回包就算失败。

## 名册

Lead 每一轮都能看到名册，写在系统提示里：

- `<team-roster>`：每个成员一行 `- 名字（状态，模型）`；还没建成员的岗位写 `- 名字（vacant）`。
- 路由规则：用户消息以 `@成员名` 开头时，把 `@成员名` 之后的原文原样转给该成员。
- 一句固定的话：「成员之间看不到彼此，只有你知道全部成员」。
- `<team-roles>`：每个可用角色一行，写明成员名、角色描述、用哪个模式、是否继承上下文。
- 派活骨架与回报骨架，正文在 `templates\通信骨架.md`。

成员侧只挂一份回报骨架，看不到名册，也看不到别的成员。成员和角色都为空时不写任何名册文本。

## 任务板唤醒

插件盯着任务板和成员状态，只在三种情况给 Lead 发一条提示：

1. 任务可以开始（`pending` 且 ready），但没有人认领。
2. 任务在做（`in_progress`），但负责人已经不在名册里。
3. 有可以开始、没人认领的活时，顺带列出空闲成员。

唤醒方式是给 Lead 排一轮 followup：Lead 空闲就立刻开一轮，忙就在这轮结束后看到。

提示只提示，不自动指派。提示里给出 `team_task_update` 改负责人、`send_message` 找人的用法，开头是 `[agent-team-roles] 任务板有变化（插件自动提示，不是用户发的消息）：`。

去重与上限：

| 项 | 规则 |
| --- | --- |
| 去重键 | 任务 id 加版本号，同一条任务的同一版本只提一次 |
| 记录上限 | 200 个键 |
| 每个 Lead 会话上限 | 8 条提示 |
| Lead 正在跑 | 跳过，不打断 |

## 生效

名册、唤醒、派发都在宿主侧。改这些要重启 dsh。
